# AI 활용 기준 면접 답변

## 핵심 답변

저는 새로운 모델이 나올 때마다 공개 벤치마크나 주변 평가만 보고 주력 도구를 변경하지 않습니다. 실제로 자주 수행하는 기존 React 저장소의 기능 추가 작업을 개인 벤치마크로 만들어 동일한 조건에서 비교합니다.

기능 정확성, 기존 기능 회귀, 프로젝트 구조 준수, 접근성과 예외 처리, 제가 검토하고 수정하는 데 걸린 시간, API 비용을 100점으로 측정합니다. 모델마다 같은 base commit에서 세 번 실행하고 중앙값을 사용합니다. 기본적으로 기존 모델보다 8점 이상 높거나, 품질과 회귀 안전성을 유지하면서 제 검토 시간을 20% 이상 줄일 때만 주력 도구를 변경합니다.

이 기준을 세운 이유는 AI가 코드를 빠르게 생성하는 것과 실제로 merge 가능한 변경을 빠르게 만드는 것은 다르기 때문입니다. AI가 작성했더라도 최종 코드를 이해하고 검증하고 책임지는 주체는 개발자라고 생각합니다.

## 한 문장

> 모델의 유행보다, 내가 아는 실제 문제에서 검증 가능한 결과를 얼마나 적은 총비용으로 만드는지를 기준으로 선택합니다.

## 이 저장소가 증명하는 것

- 말로만 기준을 설명하지 않고 동일한 fixture와 평가 절차를 공개했다.
- 자동 test 점수와 사람의 review cost를 분리했다.
- 한 번의 최고 결과가 아니라 세 번의 실행과 중앙값으로 비교한다.
- 모델 이름을 보기 전에 architecture fit을 blind review하도록 설계했다.
